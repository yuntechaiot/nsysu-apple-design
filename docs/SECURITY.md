# 安全填寫與程式碼存取

2026-10-20：每位受試者使用固定、僅可新增日誌的 QR；研究者使用指定日誌帳密，在網站管理資料。

## 提供填寫連結

1. 在正式網站選擇受試者，登入具有該受試者寫入授權的研究帳號。
2. 選擇後自動顯示這位受試者的固定 QR Code 與連結，可直接複製並提供給本人，不必手動產生。
3. 固定 QR 不因重開頁面或 30 天而變更／到期；每小時最多成功新增 5 筆，每滾動 24 小時最多 10 筆。移除受試者會停用，還原後恢復相同固定 QR。既有 30 天連結在原期限內仍可使用，但移除後不會恢復。

舊版只有 `?member=...` 的 QR Code 不能再匿名新增日誌，必須重新提供安全連結；已登入的日誌管理帳號仍可填寫。姓名與歷史紀錄仍需管理帳號授權，邀請連結不提供讀取或修改既有日誌的權限。

專屬連結代表填寫權限，請只提供給對應受試者。它不能證明持有人一定是受試者本人；若遭轉傳，可移除受試者暫停填寫，並由系統管理員撤銷／更換該受試者憑證。不能將全部受試者的 QR 開放給未登入訪客。

## 直接在網站管理

網站使用研究團隊指定的三組日誌帳密；首頁按「登入管理資料」，或在日誌／研究資料登入畫面輸入日誌帳號與密碼。使用者不需要登入 Supabase 後台，也不必填寫電子郵件。

- 三組帳號均可管理所有受試者的日誌。從網站新增受試者時，自動開通三組帳號的權限。
- 在受試者選擇頁新增受試者、修改姓名、自動查看固定 QR；已移除時不顯示可用 QR。
- 在「歷史紀錄」新增、編輯或逐筆刪除日誌。刪除前會顯示受試者、日期、姓名，必須再次確認；日誌刪除無法從網站還原。
- 「移除受試者」會從使用中清單移除並停用 QR，既有研究資料保留。勾選「顯示已移除的受試者」後可還原；還原後恢復原固定 QR；過去的臨時連結不會恢復。
- 日誌與研究 Dashboard 使用同一組日誌帳密規則；Dashboard 會以本次輸入連接 DocterCloud，平台密碼不寫入設定或資料庫，access token 只留在當前工作階段。保留單獨平台入口供帳密不同時使用。
- Dashboard 每次讀取與自動更新前，透過 `diary_staff_status` 核對目前的 staff 權限；收回權限、停用或登入失效時，清除研究快取與平台 token。日誌登出只結束當前 session。

帳密透過既有 Auth 服務驗證，原始碼不保存三組實際帳密。`diary_staff` 只能由後台管理的 `app_metadata` 開通；使用者自行修改 `user_metadata` 無法取得權限。所有研究表的 authenticated 操作另有 restrictive staff guard，會核對目前 Auth 帳號狀態；收回 staff 或停用帳號後，舊 JWT 亦不能繼續操作研究表。授權 helper 固定空 search_path，僅位於私有 schema，不能讀取其他用戶的資料或任意執行 SQL。

Supabase 後台仍可供系統管理員維護；日常資料管理不需要使用後台。新增一般 Auth 帳號不會自動得到網站管理權限，也不會自動成為這三組日誌帳號。

## 資料庫控制

- 收回 `anon` 對 `sleep_logs` 的直接 INSERT，移除原匿名新增 policy；不能跳過網頁而直接寫入。
- `submit_invited_diary` 驗證高強度亂數邀請、對應編號、到期／停用狀態、固定欄位與原日期／數值約束。
- 固定邀請使用兩個加密亂數 UUID，共 244 位元隨機性；驗證表只保存 SHA-256，固定憑證以 Supabase Vault 加密保存，確保跨頁面仍可取得相同 QR。僅核對當前 staff 與對應受試者寫入授權的 private helper 可取得單一憑證；anon／authenticated 無 Vault 表或解密 view 讀取權限。詳見 [Supabase Vault](https://supabase.com/docs/guides/database/vault)。
- 同一受試者的提交以資料庫列鎖序列化；配額按受試者計算，換連結不會重設。
- 每次新增具有唯一請求識別碼；網路中斷後重送相同內容不會新增重複日誌。相同識別碼搭配不同內容會拒絕。
- 具寫入授權的研究者保留原 RLS 操作，不受受試者邀請配額限制；配額保護的是公開填寫入口。

私有 schema `nsysu_private` 保存雜湊與提交收據，對瀏覽器角色沒有資料表權限，並啟用 RLS。狹義 SECURITY DEFINER helper 僅在非 Data API schema 內，固定空 search_path、完整限定資料表名稱、固定 INSERT 欄位；公開 RPC wrapper 為 SECURITY INVOKER。這些 helper 不提供動態 SQL、任意資料查詢或歷史讀取。不能把 `nsysu_private` 加入 Data API 的 exposed schemas。

Supabase Publishable Key 可交給瀏覽器；service_role／secret key 不會提供給網站。連結使用 HTTPS，頁面設定 no-referrer，不載入第三方 QR 圖片服務。邀請可能存在瀏覽器紀錄與代管平台請求紀錄，應按填寫憑證管理；本機限流不能取代平台的整體流量防護。

## GitHub 與部署

原始碼可放私人 GitHub repository，Streamlit 需具有該 repository 的讀取權限，app 的 Sharing 維持 public。隱藏原始碼不能取代上述資料庫權限。

實際 `.env`、Secrets、研究資料與私人備份持續排除 Git。SQL migration 不刪除或改寫既有研究紀錄；安全邀請與 staff 網頁管理均保留在版本控制的 migrations。

## 驗證範圍

本機 PGlite 使用合成資料驗證直接寫入拒絕、跨受試者拒絕、雜湊、固定連結一致性、舊連結有效期、撤銷、每小時／24 小時配額、重送與原資料保留。瀏覽器測試攔截全部 Supabase 請求，驗證安全 QR、登入、四步驟表單與歷史編輯；正式資料庫驗證只用中繼資料與無效邀請，不將假日誌寫入研究紀錄。
